# Прокорми монстра

Вертикальная (9:16) web-игра о финансовой грамотности: ребёнок заводит 3D-монстрика, кормит и чистит его, планирует бюджет, копит на цели и проходит экономические эпизоды вместе с ментором.

> [!IMPORTANT]
> **Играйте со звуком.** Реплики ментора, монстрика, папы и тренера озвучены, и многое в игре объясняется именно голосом. Без звука часть подсказок легко пропустить.

> [!TIP]
> **Не пропускайте туториалы.** В них рассказывается не только о том, куда нажимать, но и об игровых механиках: как устроен бюджет, копилка, карман, дни игры и экономические эпизоды. Без туториалов дальнейшие задания будут непонятны.

## Режим жюри

Чтобы быстро посмотреть любой эпизод, не проходя игру заново, есть панель жюри.

1. Создайте монстрика и дойдите до его комнаты.
2. В нижней панели комнаты **нажмите и удерживайте кнопку профилей 👥 около 3 секунд**. Вокруг кнопки заполняется кольцо; когда оно замкнётся, откроется **«Панель жюри» 🏅**.
3. Содержимое игры собрано в раскрывающиеся группы: экономические эпизоды, дополнительные задания, реплики, туториалы и т. д. Кнопка ▶ у строки:
   - у эпизода или задания — перезапускает игру прямо в этом эпизоде (после перезагрузки нажмите «Запустить», чтобы браузер разрешил звук);
   - у реплики — проигрывает её озвучку прямо в панели.
4. Эпизоды запускаются в отдельной «песочнице жюри», поэтому **прогресс игрока не меняется**. Вернуться к своей игре можно кнопкой «Вернуться к своему монстрику» в панели жюри или просто перезагрузив страницу.

Короткое нажатие на 👥 открывает обычный список профилей, а не панель жюри.

## Родительский режим

1. В комнате монстрика нажмите кнопку профилей **👥**.
2. В списке профилей у нужного монстрика нажмите **«Родительский контроль»**.
3. Откроется журнал игры по дням. Переключатель вверху показывает либо все записи, либо только экономические события: эпизоды, верные и ошибочные финансовые решения.

В том же окне можно войти в другой профиль («Войти») или начать игру заново с новым монстриком. Прогресс хранится в браузере (localStorage), поэтому профили видны только на том компьютере и в том браузере, где в них играли.

## Как запустить игру на своём компьютере

Ниже пошаговая инструкция для тех, кто ни разу не запускал такие проекты. Команды одинаковые для Windows, macOS и Linux, если не сказано иначе.

### 1. Установите нужные программы

| Программа | Зачем | Где взять |
|---|---|---|
| **Node.js 20 LTS или новее** (вместе с ним ставится `npm`) | запускает локальный сервер игры | [nodejs.org](https://nodejs.org/) → кнопка **LTS** |
| **Git** (необязательно) | скачивает репозиторий | [git-scm.com/downloads](https://git-scm.com/downloads) |
| **Google Chrome** или другой современный браузер с WebGL | в нём идёт игра | [google.com/chrome](https://www.google.com/chrome/) |

После установки Node.js **закройте и заново откройте терминал**, чтобы он увидел новые команды. Проверьте установку:

```bash
node -v
```

```bash
npm -v
```

Первая команда должна вывести версию не ниже `v20`, вторая — любой номер версии. Если пишет «команда не найдена», перезагрузите компьютер и попробуйте снова.

Где открыть терминал:
- **Windows** — меню «Пуск» → наберите `PowerShell` → Enter.
- **macOS** — Spotlight (⌘ + пробел) → `Терминал`.
- **Linux** — `Ctrl + Alt + T`.

### 2. Скачайте проект

**Вариант А — через Git** (удобно получать обновления):

```bash
git clone https://github.com/Evsikoff/prokormi.git
```

```bash
cd prokormi
```

**Вариант Б — без Git.** На странице репозитория нажмите зелёную кнопку **Code** → **Download ZIP**, распакуйте архив, затем откройте терминал в распакованной папке `prokormi-main`. Проще всего перейти в неё командой `cd`, указав путь к папке, например:

```bash
cd ~/Downloads/prokormi-main
```

> [!NOTE]
> Репозиторий весит около 300 МБ: в нём лежат видео, музыка, озвучка и 3D-модели. Скачивание может занять несколько минут.

Дальше все команды выполняются **в папке проекта** — той, где лежит файл `package.json`.

### 3. Установите зависимости

```bash
npm install
```

Команда скачает библиотеки (Vite и Three.js) в папку `node_modules`. Это нужно сделать один раз, а также после каждого обновления проекта. Предупреждения (`npm warn`) можно не читать; главное, чтобы в конце не было строки `npm error`.

### 4. Запустите игру

```bash
npm run dev
```

Через пару секунд в терминале появится примерно такое:

```text
  VITE v6.4.3  ready in 900 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.1.10:5173/
```

Откройте в браузере адрес из строки **Local** — обычно это [http://localhost:5173/](http://localhost:5173/). Нажмите «Играть» и **включите звук**.

- Пока игра запущена, окно терминала закрывать нельзя. Чтобы остановить сервер, нажмите в терминале `Ctrl + C`.
- **Поиграть с телефона:** если телефон подключён к той же Wi-Fi-сети, что и компьютер, откройте на телефоне адрес из строки **Network**. Если страница не открывается, разрешите Node.js доступ к сети в брандмауэре (Windows спросит об этом при первом запуске).
- Интернет для самой игры не нужен: все данные, звуки и модели лежат в проекте.

### 5. (Необязательно) Запустите собранную версию

Так игра работает быстрее, ровно как на хостинге:

```bash
npm run build
```

```bash
npm run preview
```

Откройте адрес, который напишет вторая команда, обычно [http://localhost:4173/](http://localhost:4173/). У этого адреса свой прогресс: профили, созданные на `localhost:5173`, здесь не видны.

### Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `node` или `npm` — «не является командой» / `command not found` | Node.js не установлен или терминал открыт до установки. Переоткройте терминал или перезагрузите компьютер. |
| `npm error` при `npm install` про версию или синтаксис | Слишком старый Node.js. Установите LTS-версию с [nodejs.org](https://nodejs.org/). |
| `Port 5173 is in use` | Игра уже запущена в другом окне терминала. Vite сам возьмёт следующий порт (5174 и т. д.) — откройте адрес, который он напишет. |
| `npm error enoent … package.json` | Терминал открыт не в той папке. Перейдите командой `cd` в папку, где лежит `package.json`. |
| Чёрный экран вместо комнаты или монстрика | Браузер не поддерживает WebGL или у него выключено аппаратное ускорение. Откройте игру в свежем Chrome. |
| Нет звука | Проверьте громкость и что вкладка не заглушена. Браузер включает звук только после нажатия на кнопку «Играть». |
| Хочется начать всё с нуля | 👥 → «Начать игру заново с новым профилем». Старые профили останутся в списке. |

## Для разработчиков

### Данные из Supabase

Файл `monster_data_mart_rows.json` (реплики, туториалы, эпизоды, товары и т. д.) собирается из таблицы `monster_data_mart` в Supabase. Для запуска игры это не нужно — файл уже лежит в репозитории.

1. Скопируй `.env.example` в `.env.local` и впиши `SUPABASE_URL` и `SUPABASE_KEY` (лучше secret-ключ `sb_secret_...`).
2. Выгрузи таблицу:

```bash
npm run data:pull
```

Колонки JSONB попадают в файл вложенными объектами, а не строками. Если JSON случайно сохранён в ячейку строкой, скрипт превратит его в объект и напишет, в каких строках это случилось. Файл встраивается в игру при сборке, поэтому после выгрузки нужен `npm run build`; `npm run dev` подхватит изменения сам.

`data:pull` перезаписывает файл целиком: правки, которые ещё не отправлены в Supabase, пропадут.

#### Обратно: из файла в Supabase

Сначала посмотри, что изменится (в базу ничего не пишется):

```bash
npm run data:push -- --dry-run
```

Потом отправь:

```bash
npm run data:push
```

- Строки сопоставляются по `id`. Строка с `id`, которого нет в таблице, добавляется; строка без `id` тоже добавляется, а `id` ей выдаёт база.
- В существующих строках меняются только ячейки, которые отличаются от таблицы. Колонку можно не указывать — тогда она останется как в таблице.
- Строки, которых нет в файле, по умолчанию не трогаются. Чтобы удалить их из таблицы, добавь `--delete`: `npm run data:push -- --delete`.
- После записи в файл возвращается то, что заполнила база (новые `id`, `created_at` по умолчанию, формат дат).
- Перед записью файл проверяется целиком: повторяющиеся `id` и колонки, которых нет в таблице, останавливают отправку.

Нужен secret-ключ: publishable-ключу запись обычно запрещена политиками RLS.

### Озвучка туториала

Тексты шагов лежат в `public/tutorial/tutorial.json`. Аудиофайлы можно положить рядом и указать имя файла в поле `audio`, например `"audio": "tut1.wav"`. Поддерживаются WAV и MP3. Если поле `audio` равно `null`, подсказка работает только с текстом.

Браузеры запрещают автоматически включать звук без действия пользователя. Поэтому приложение сначала пытается запуститься само, а если браузер блокирует звук, показывает дружелюбную кнопку «Играть».

### Деплой на Vercel

Проект — обычное Vite-приложение, поэтому Vercel собирает его без дополнительной настройки. Параметры продублированы в `vercel.json`: `npm ci` → `npm run build` → каталог `dist`.

1. На [vercel.com/new](https://vercel.com/new) выбери репозиторий `Evsikoff/prokormi` и нажми **Import**.
2. Framework Preset определится как **Vite**, Build Command `npm run build`, Output Directory `dist` — менять ничего не нужно.
3. **Deploy**. Переменные окружения не нужны: `SUPABASE_URL` и `SUPABASE_KEY` используются только локальными скриптами `npm run data:pull` / `npm run data:push`, в браузер они не попадают.

Данные вшиваются в сборку из `monster_data_mart_rows.json`, поэтому после `npm run data:pull` нужен новый коммит — Vercel пересоберёт приложение сам.

Тяжёлые ассеты (видео, музыка, `.glb`-модели комнаты и парка) лежат в репозитории и раздаются как статика — на бесплатном тарифе следи за расходом трафика.

Рабочие материалы дизайна (`room-design/`, `park-design/`) в репозиторий не выкладываются: в сборке они не участвуют и весят больше самого приложения.
